## Detailed Findings

### [P1] Repeated site chrome is inside the main landmark with no keyboard bypass

- **Location:** `app/page.tsx`, `app/catalog/page.tsx`, `app/examples/page.tsx`
- **Category:** Accessibility / Implementation Integrity
- **Impact:** Keyboard users cannot bypass the repeated header navigation, and
  assistive technology receives a `main` landmark that includes the header and,
  on the landing/catalog pages, the footer rather than only page-specific content.
- **WCAG/Standard:** WCAG 2.4.1 Bypass Blocks; HTML landmark semantics.
- **Recommendation:** Give the custom shell a header/main/footer structure, add
  a visible-on-focus skip link to a stable `#main-content` target, and keep the
  current visual composition unchanged.
- **Suggested command:** `$impeccable harden`

### [P2] Mobile docs chrome undershoots the 44px target floor

- **Location:** Fumadocs `#nd-subnav` and TOC popover, styled from `app/global.css`
- **Category:** Responsive / Accessibility
- **Impact:** The mobile Search and Sidebar buttons measure 34×34px; the sticky
  page-progress button measures 40px tall; the docs wordmark is 24px tall.
  They remain usable and exceed WCAG 2.5.8's 24px minimum, but are less forgiving
  for touch and miss the project's chosen 44px floor.
- **WCAG/Standard:** WCAG 2.5.8 Target Size (Minimum); 44px platform convention.
- **Recommendation:** Add scoped minimum dimensions to the mobile Fumadocs
  subnav controls, TOC popover button, and wordmark without changing desktop chrome.
- **Suggested command:** `$impeccable adapt`

### [P2] Choosing Fidelity skips from page title to an evidence `h3`

- **Location:** `components/guide-evidence.tsx`, FidelityWorkbench ledger title
- **Category:** Accessibility / Implementation Integrity
- **Impact:** The first dynamically selected evidence heading follows the page
  `h1` as an `h3`, creating a structural gap for heading navigation even though
  the visual hierarchy is clear.
- **WCAG/Standard:** WCAG 1.3.1 Info and Relationships (semantic best practice).
- **Recommendation:** Use an `h2` for the selected evidence decision title or
  label the region without introducing a skipped heading level.
- **Suggested command:** `$impeccable harden`

### [P2] Reduced motion uses a global near-zero-duration kill switch

- **Location:** `app/global.css`, global `prefers-reduced-motion` block
- **Category:** Accessibility
- **Impact:** The blanket `0.01ms` override prevents motion discomfort, but also
  erases useful component-level transition feedback indiscriminately. The catalog
  and guide already have more intentional reduced-motion rules that can preserve
  state hierarchy without animation.
- **WCAG/Standard:** WCAG 2.3.3 Animation from Interactions; user preference intent.
- **Recommendation:** Replace the global duration override with explicit static
  end states and component-scoped transition removal.
- **Suggested command:** `$impeccable animate`

### [P2] Catalog mode changes animate layout properties across many specimens

- **Location:** `components/catalog-explorer.module.css:458-481`
- **Category:** Performance
- **Impact:** Width, grid columns, gap, padding, and font size transition during
  Expanded/Compact changes. This is a bounded user action, not continuous
  thrashing, but the dense catalog can incur avoidable layout and paint work.
- **WCAG/Standard:** Rendering-performance best practice; detector
  `layout-transition` warning.
- **Recommendation:** Let View Transitions carry the mode change and restrict
  component animation to transform/opacity, while preserving the compacting
  spatial story and reduced-motion static end state.
- **Suggested command:** `$impeccable optimize`

### [P2] Implemented tonal/type/radius values outpace `design.md`

- **Location:** `app/global.css`, `components/catalog-explorer.module.css`,
  `components/guide-evidence.module.css`, `design.md`
- **Category:** Theming / Implementation Integrity
- **Impact:** The UI is visually coherent, but 61 type-step, 23 color, and four
  radius advisories cannot be classified reliably as intentional primitives or
  one-off values. Future work is more likely to drift or duplicate near-matches.
- **WCAG/Standard:** Design-system maintainability.
- **Recommendation:** Extract the implemented tonal ramps, editorial type steps,
  radii, and motion curves; merge intentional values into the documented system;
  replace genuine one-offs with the reconciled tokens.
- **Suggested command:** `$impeccable extract`

## Patterns & Systemic Issues

- The main technical debt is **documentation drift**, not visual incoherence.
  The implementation has a stable design language, while the design-system file
  describes too few of the tonal and editorial steps now in production.
- The remaining **touch-target gap is isolated to Fumadocs mobile chrome**. The
  custom landing, Catalog, Examples, guide evidence controls, handoff links, and
  catalog actions meet the 44px height floor after adaptation.
- The catalog's motion is purposeful and reduced-motion aware, but its mode
  transition currently asks layout to animate more than necessary.

- Current-route state, mobile-menu state, Escape behavior, focus restoration,
  catalog URL state, popstate recovery, subject-anchor focus, and tablist arrow/
  Home/End behavior all work.
- Every tested route has a single visible `h1`, no duplicate IDs, no missing image

- The 320px pass found no horizontal document overflow or clipped page titles.
- The server stayed live throughout the audit and all audited routes returned 200.
